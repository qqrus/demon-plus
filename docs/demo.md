# Демонстрация за пять минут

Первичная подготовка данных и обучение выполняются заранее:

```bash
docker compose up -d --build
```

Откройте http://127.0.0.1:8502 после завершения `init`.
При первом запуске дата истории — 2018-06-30; повторный запуск сохраняет загруженные
факты. На скриншотах README история уже обновлена до 2018-07-30.

1. **Бизнес-задача.** Интернет-магазину нужно понимать ожидаемые продажи и запас.
   Здесь прогнозируется категория; доступность конкретного SKU из него не следует.
2. **Прогноз.** Выберите «Текстиль для дома» и 14 дней. Постройте прогноз,
   покажите историю, дату среза и выгрузку CSV. Дробные значения — ожидаемые продажи.
3. **Запасы.** Оставьте пометку синтетического примера, рассчитайте риски.
   Объясните первый день дефицита и влияние даты поставки; это сценарий,
   а не оценка вероятности. В Olist нет настоящих складских остатков.
4. **Качество.** Покажите baseline и CatBoost на одинаковых временных срезах.
   На итоговом 30-дневном тесте WAPE: 39.11% против 36.73%.
   На других метриках улучшение не универсально; один месяц не доказывает устойчивость.
5. **Обновление.** В разделе «Данные» покажите формат CSV и валидацию.
   Загрузка создаёт версию продаж. Переобучение не заменяет модель автоматически:
   сначала сравнение, затем отдельное применение допущенного кандидата.
6. **Мониторинг.** Объясните различие data drift и quality drift. Без фактов
   нет оценки ошибки. Для сравнения нужны два полных неперекрывающихся горизонта
   одной модели и категории. [Подготовка такого сценария](monitoring.md#демонстрация).

Подготовка реального исторического CSV:

```bash
docker compose exec api python -m demon_plus.data.demo_update
docker compose cp api:/app/data/demo/sales-update.csv ./sales-update.csv
```

Этот файл можно повторно загрузить без удвоения продаж. Новая категория, пропуск дня
или исправление прошлой продажи отклоняются с сообщением. Для quality drift
загружайте факты по частям согласно методике; если июль уже загружен целиком,
исторические прогнозы нельзя честно создать задним числом.

## Что объяснить на собеседовании

- Временная валидация и признаки только из доступной на дату прогноза истории.
- Простая baseline-модель как обязательная точка сравнения.
- MLflow связывает параметры, метрики и модель; SQLite связывает прогноз с версиями.
- Разделение обучения, API и интерфейса позволяет тестировать бизнес-правила отдельно.
- Пороги drift эвристические; мониторинг запускается при открытии раздела, без scheduler.
- Следующие production-шаги: авторизация, очереди, резервные копии, PostgreSQL,
  мониторинг задержек и интервалы неопределённости.
