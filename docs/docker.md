# Запуск в Docker

Нужен Docker с Linux-контейнерами и Compose v2 с поддержкой необязательного env_file
(2.24 или новее). Из корня репозитория:

```bash
docker compose up -d --build
```

Первый запуск скачивает Olist, обучает модели, сохраняет MLflow и оценивает holdout.
Это занимает несколько минут; прогресс: `docker compose logs -f init`.
Затем стартуют API и интерфейс:

- Streamlit: http://127.0.0.1:8502
- API/Swagger: http://127.0.0.1:8001/docs

Порты отличаются от запуска через uv, поэтому оба варианта могут работать одновременно.
Повторный запуск использует подготовленную модель и сохранённую оценку.
Контейнеры работают от обычного пользователя, API — в одном процессе.
UI запускается после успешной проверки готовности API, API — после подготовки данных.

Данные и артефакты находятся в отдельных именованных томах Docker (`sales`, `artifacts`).
Они не используют локальные Windows SQLite-файлы: в них сохранены абсолютные пути,
которые нельзя переносить между ОС простым копированием БД.
`.env` подключается при наличии, пути внутри контейнера переопределены в Compose.
Секреты, локальные данные и окружение исключены из контекста сборки через `.dockerignore`.

Остановка с сохранением данных:

```bash
docker compose down
```

Не добавляйте `-v`, если хотите сохранить обучение, загруженные продажи и прогнозы.

Подготовить демонстрационный CSV внутри контейнера:

```bash
docker compose exec api python -m demon_plus.data.demo_update
docker compose cp api:/app/data/demo/sales-update.csv ./sales-update.csv
```

Затем загрузите CSV в Streamlit; не коммитьте его. Локальный вариант экспорта
в `data/demo` описан в [application.md](application.md).

CI проверяет Ruff, mypy, тесты на Windows/Linux и сборку пакета.
Отдельная Linux-задача проверяет Compose, собирает Docker-образ, запускает CLI и API
без модели, проверяя корректный статус `ready=false`. Полное обучение с загрузкой
внешнего датасета выполняется при локальной приёмке, не на каждом pull request.
Публикация образа и автоматическое развёртывание не настроены.
