# Разработка

## Окружение и проверки

Из корня репозитория:

```bash
uv sync --locked
uv run --locked python -X utf8 -m pre_commit install
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy
uv run --locked pytest
```

`uv.lock` фиксирует разрешённые версии зависимостей. `--locked` запрещает незаметно
обновить lock-файл. Уже добавлены pandas, NumPy, scikit-learn и matplotlib;
CatBoost, MLflow, FastAPI, Streamlit и Evidently также зафиксированы в lock-файле.
`src-layout` проверяет импорт установленного пакета, а не случайный
импорт из текущей папки.

Pre-commit запускает ruff, проверку форматирования и mypy из того же окружения.
Полный pytest запускается после этапа и в CI. Тесты изолированы от локального
`.env` и переменных `DEMON_PLUS_*` разработчика.

При установке hook включаем `-X utf8`: на Windows это сохраняет путь к Python
с кириллицей в кодировке, которую понимает Git. После установки можно выполнять
обычный `git commit` без ручной активации окружения; `uv` должен быть доступен в PATH.

## Реализованная структура

```text
src/demon_plus/
  __init__.py
  config.py       # типизированные настройки
  logging.py      # JSON в stderr
  schemas.py      # публичный результат проверки
  cli.py          # check, fetch-data, baseline, train, evaluate-model
  errors.py       # ожидаемые ошибки данных
  data/           # загрузка и проверка Olist, дневная панель
  features/       # общие признаки обучения и предсказания
  models/         # baseline, CatBoost, сохранение/загрузка
  evaluation/     # временные срезы, обучение, MLflow, метрики, отчёты
  api/            # FastAPI и Pydantic-контракты
  ui/             # Streamlit, HTTP-клиент API
  inventory/      # остатки, поставки и первый день дефицита
  monitoring/     # Evidently и оценка сохранённых прогнозов
  storage/        # SQLite через SQLAlchemy
  service.py      # версии данных, прогнозы, переобучение
  bootstrap.py    # подготовка Docker-демо
  py.typed        # пакет предоставляет типы
tests/            # конфигурация, CLI, данные, прогнозы, сквозной pipeline
docs/             # решения и план
```

Streamlit обращается к REST API; бизнес-правила и хранение не зависят от интерфейса.

## Конфигурация и сообщения

Локальные настройки — `.env`, образец — `.env.example`. В контейнерах значения
можно передавать через окружение. Для секретных значений при добавлении интеграций
будет использоваться `SecretStr`. Нельзя логировать `.env`, настройки целиком,
учётные данные или содержимое пользовательских файлов.

`check` принимает только команду, а не настройки. Ожидаемые ошибки чтения
и валидации конфигурации дают понятное сообщение и код `2`, без входных значений.
Неожиданные программные ошибки не маскируются успешным ответом.

## Git

- Работать в feature-ветках `codex/...`.
- Делать небольшие коммиты по смыслу; включать связанные тесты.
- Перед push или созданием PR показать пользователю краткий список изменений
  и дождаться его явного подтверждения.
- После каждого этапа запустить релевантные проверки и сообщить результаты.
- Не добавлять `.env`, датасеты, модели, локальные БД, MLflow-артефакты и логи в Git.

Удалённый репозиторий пока не настроен. CI подготовлен для PR и push в `main`.

## Решения этапа 1

- `uv` управляет Python, окружением и lock-файлом. Документация:
  https://docs.astral.sh/uv/guides/projects/
- `pydantic-settings` проверяет конфигурацию и поддерживает окружение и `.env`:
  https://docs.pydantic.dev/latest/concepts/pydantic_settings/
- `structlog` формирует события JSON; stdout остаётся пригодным для обработки
  результата CLI другими программами.
- `mypy --strict` обнаруживает проблемы с типами; pytest проверяет поведение.
- Минимальный CI появляется сразу, Docker и ML-зависимости — позже.

Проверка конфигурации не создаёт БД и не проверяет существование обученной модели.

## Этап 2

```bash
uv run --locked demon-plus fetch-data
uv run --locked demon-plus baseline
uv run --locked pytest -W error
```

Настройки временных срезов находятся в `.env.example`; `.env` с этапа 1 можно
оставить — новые поля имеют те же значения по умолчанию. `validation_cutoffs`
в `.env` задаётся JSON-массивом дат. Срезы должны идти по возрастанию, иметь
30-дневные непересекающиеся целевые окна, а holdout — следовать за ними.

Тесты работают на синтетических мини-таблицах, не скачивают Olist и не требуют сети.
Сквозной тест проверяет также запись отчётов, повторяемость метрик и исключение
holdout из прогнозных результатов. Модели принимают уже отрезанную историю:
это отделяет расчёт прогноза от доступа к будущим фактам.

Для pandas установлены типовые описания `pandas-stubs`. Для `sklearn.*` и `catboost.*`, где
установленная библиотека не предоставляет подходящих описаний типов,
ограниченно разрешён `ignore_missing_imports`; остальной код проверяется строго.
Граница библиотеки закрыта типизированной функцией `regression_metrics` и тестами.

Небольшие отчёты `docs/results` — снимок локального прогона для чтения на GitHub.
После изменения данных/протокола его нужно обновлять вместе с метриками README.
Подробные прогнозы, обработанные данные и исходный архив в Git не включаются.

## Этап 3

См. [modeling.md](modeling.md): параметры, признаки, локальное хранилище MLflow
и команды train/evaluate-model. Сквозной тест использует маленькие синтетические
CSV, пять деревьев и временную SQLite, проверяя реальные вызовы CatBoost и MLflow.
Сетевые сервисы и скачивание Olist для тестов не нужны.

Дополнительные проверки: инвариантность признаков/обучающих целей к изменениям
после cutoff, совпадение признаков обучения и инференса, целостность `.cbm`,
совпадение прогнозов после загрузки, запрет прогноза моделью из будущего,
запись метрик/артефактов в MLflow и замороженный holdout.
