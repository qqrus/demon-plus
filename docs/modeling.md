# CatBoost и MLflow

## Постановка

Одна глобальная модель обучается на десяти категориях из этапа 2. Строка обучения
описывает категорию, дату выпуска прогноза и горизонт от 1 до 30 дней. Цель —
заказанные единицы в конкретный будущий день. Для графика на 7/14/30 дней используем
первые соответствующие дни одного прямого прогноза. Ошибки предыдущих предсказаний
не подаются обратно как лаги.

Признаки на конец дня `origin`:

| Группа | Признаки | Доступность |
|---|---|---|
| Идентификатор | category | Зафиксированный справочник |
| Горизонт | step = 1..30 | Известен при запросе |
| Календарь цели | день недели, месяц, день месяца, выходной | Известен заранее |
| Прошлые продажи | lag_0, lag_6, lag_13, lag_27 | Относительно origin, включая сам origin |
| Окна | средние за 7/14/28 дней, std и доля нулей за 28 дней | Только дни <= origin |
| Недельная сезонность | среднее того же дня недели за последние 28 дней | Четыре прошлых значения |

`lag_0` допустим: прогноз выпускается после окончания дня origin и начинается
на следующий день. Будущая цена, доставка, финальный статус заказа и будущие
продажи в признаки не включаются.

`feature_rows` сначала отрезает данные по origin, затем проверяет и вычисляет
признаки. `training_rows` использует только origins, для которых все 30 целевых
дней уже наступили к cutoff обучения. Первые 28 дней нужны для признаков.
Обучающие origins берём каждые семь дней: это уменьшает размер учебного проекта,
сохраняя все 30 горизонтов. Один целевой день может встречаться у разных origins;
это зависимые примеры, а не независимые наблюдения для статистического теста.

## Параметры и честное сравнение

Заранее заданные кандидаты: глубина 4 и 6, по 300 деревьев, learning_rate=0.05,
loss=MAE, random_seed=42, CPU с двумя потоками. MAE выбрана, поскольку WAPE
при фиксированных фактах пропорциональна суммарной абсолютной ошибке.
Категория кодируется самим CatBoost: `one_hot_max_size=255` покрывает все наши
десять категорий и исключает необходимость target encoding.

В каждом срезе модель обучается заново на прошлых данных. Early stopping по
оцениваемому окну не применяется. Кандидат выбирается по объединённому дневному
WAPE для 30 дней на трёх прежних срезах. Оба baseline пересчитываются в том же
запуске. Если baseline окажется лучше, selection.json сохранит это решение.

После выбора лучшего CatBoost он переобучается на доступной истории до
2018-06-30. Команда train не оценивает июльские цели. Отдельная evaluate-model
оценивает замороженную модель и оба baseline на 2018-07-01—2018-07-30.
Повторный вызов возвращает уже записанный результат. После просмотра holdout
нельзя настраивать модель по нему и продолжать называть его независимым тестом.

## Запуск и артефакты

Из корня проекта после загрузки Olist:

```bash
uv run --locked demon-plus train
uv run --locked demon-plus evaluate-model
```

Настройки задаются в `.env`; образец включает глубины, число деревьев,
шаг обучающих origins, seed и путь SQLite для MLflow. Константы определения
модели (MAE, learning_rate, список признаков) версионируются как код.

Каждый train создаёт уникальный каталог `artifacts/training/<run_id>`.
`latest.json` указывает на последний успешно завершённый запуск. Содержимое:

- `selection.json`: решение по валидации, категории, параметры, хеши данных/кода,
  версии ML-библиотек и дата обучения;
- `validation_metrics.json` и `validation_predictions.csv`;
- `model/model.cbm` и `model/metadata.json`: нативная модель и её контракт;
- `feature_importance.csv`: важность по изменению предсказаний CatBoost;
- после evaluate-model — `holdout_metrics.json`, `holdout_predictions.csv`,
  `report.md` и `holdout_forecast.png`.

Загрузка модели проверяет SHA-256 файла и список признаков. Предсказание требует
того же порядка категорий и origin не раньше даты обучения. Значения ниже нуля
обрезаются до нуля одинаково при оценке и использовании. При сохранении сравниваются
предсказания до и после загрузки с абсолютным допуском 1e-12.
Файл модели не содержит истории продаж: для новых признаков нужны последние 28 дней.
Важность признаков не означает причинность и не заменяет проверку на временных срезах.

## MLflow локально

Метаданные экспериментов хранятся в SQLite, по умолчанию `artifacts/mlflow.db`.
Артефакты — в локальном `artifacts/mlflow-artifacts`. Эксперимент `demon-plus`
содержит общий запуск выбора, дочерние запуски baseline, каждого кандидата/среза
и финальной модели. Итоговый тест — отдельный запуск со ссылкой на выбор модели.
Логируются MAE/RMSE/WAPE дневных прогнозов и сумм за каждый горизонт.
Модель сохраняется в MLflow как нативный `.cbm` с JSON-метаданными;
MLflow Model Registry и автоматическое продвижение версии пока не используются.

Открыть UI при стандартном `.env`:

```bash
uv run --locked mlflow server --backend-store-uri sqlite:///artifacts/mlflow.db --host 127.0.0.1 --port 5000
```

Затем открыть http://127.0.0.1:5000. Если путь БД изменён в `.env`, передайте
соответствующий backend-store-uri. Сервер нужен только для просмотра UI:
обучение напрямую записывает данные в локальную БД. БД и модели исключены из Git.

Совместимость: ограничения NumPy <2.4 и SQLAlchemy <2.1 зафиксированы в pyproject
после проверки предупреждений pandas 2.3 и MLflow. uv.lock фиксирует точные версии.
Первый пробный запуск и повтор с совместимыми зависимостями остаются в MLflow;
параметры кандидатов не менялись, holdout между ними не оценивался.

Документация: [CatBoostRegressor](https://catboost.ai/docs/en/concepts/python-reference_catboostregressor),
[MLflow Tracking](https://mlflow.org/docs/latest/ml/tracking/).
